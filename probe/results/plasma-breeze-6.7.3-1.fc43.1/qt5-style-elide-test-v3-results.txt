=== SE_ItemViewItemText rect probe v3 (Qt5, slack-aware width sweep) ===
advance = fontMetrics.horizontalAdvance(text)  width of the glyphs themselves
tMargin = pixelMetric(PM_FocusFrameHMargin) + 1  per-side padding QCommonStyle reserves
natural = advance + 2*tMargin                 what QCommonStyle allocates to the text
drawn   = textWidth - 2*tMargin               viewItemDrawText() removes tMargin from
                                              each side again before eliding, so this,
                                              not textWidth, is the layout width
slack   = drawn - advance                     negative = cannot fit; delegate elides
elides  = elidedText(text, ElideRight, drawn) != text
diff    = itemWidth - textWidth               NOTE: regime-dependent. Where the Qt5
                                              clamp caps textWidth at `natural`, diff
                                              grows with itemWidth and does NOT mean
                                              'pixels taken by the style'. The sound
                                              cross-style measure is breeze vs Fusion
                                              textWidth at the same itemWidth.

=== opt.widget fidelity: what leaving QStyleOptionViewItem::widget null costs ===
QStyleOption::initFrom() does not assign QStyleOptionViewItem::widget. Breeze reads
option->widget in Helper::itemViewItemMargins() to detect a QFrame::StyledPanel and,
when it finds one, reduces the left/right margins by 1 each (breezehelper.cpp:1777-1780,
"Breeze frame has one extra white pixel"). Every real item view has that frame.

v1 and v2 leave opt.widget null and therefore measure the UNFRAMED case. The rows
above set it, and so measure what a real framed QListWidget receives. This section
shows both, so the difference between this probe and v1/v2 is documented rather than
looking like an inconsistency.
